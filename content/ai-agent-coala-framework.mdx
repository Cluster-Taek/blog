## 1. 에이전트는 어떻게 "생각"하는가

{/*
  - Cognitive Architectures for Language Agents (CoALA) 논문 소개
    - 인지심리학의 기억 분류를 에이전트 설계에 적용
  - 인간의 기억 유형 → 에이전트 설계에 대응시키는 발상이 왜 유효한가
  - 개발자가 이 프레임워크를 알아야 하는 이유:
    - 에이전트의 실패 원인을 구조적으로 파악할 수 있음
    - 보완 전략이 명확해짐
*/}



## 2. CoALA의 네 가지 메모리 계층

{/*
  각 유형별로: 정의 → 실무 대응 → 한계 순으로 설명
  인간의 기억 유형과 에이전트 컴포넌트를 대응시키는 것이 핵심

  - Working Memory (작업 기억)
    - 지금 읽고 있는 문장처럼, 지금 이 순간 쓰이는 정보
    - 에이전트: 프롬프트 컨텍스트, 현재 목표, 직전 관찰
    - 한계: 컨텍스트 윈도우 크기 제한

  - Episodic Memory (일화 기억)
    - 어제 저녁에 먹은 것처럼, 과거 경험을 시간순으로 보관
    - 에이전트: 대화 이력, 작업 궤적, 성공·실패 기록
    - 한계: 세션이 바뀌면 리셋 → 세션 분리 리뷰의 이론적 근거

  - Semantic Memory (의미 기억)
    - "서울은 한국의 수도"처럼 세계에 대한 사실적 지식
    - 에이전트: 지식 베이스, 도메인 규칙, CONTEXT.md, RAG
    - 한계: 주입하지 않으면 존재하지 않음 → 환각의 주된 원인

  - Procedural Memory (절차 기억)
    - 자전거 타는 법처럼 "어떻게 하는지"에 대한 지식
    - 에이전트: LLM 가중치(암묵적) + 에이전트 코드(명시적)
    - 한계: 개발자가 직접 수정 불가 (모델 선택으로만 영향)
*/}

| 메모리 유형 | 인간의 예시 | 에이전트 대응 | 개발자 제어 가능성 |
|-------------|------------|--------------|------------------|
| Working (작업) | 지금 읽는 문장 | 프롬프트 컨텍스트, system prompt | 높음 |
| Episodic (일화) | 어제 저녁 메뉴 | 대화 이력, few-shot 예시 | 중간 |
| Semantic (의미) | 서울은 한국의 수도 | CONTEXT.md, Rule 파일, RAG | 높음 |
| Procedural (절차) | 자전거 타는 법 | LLM 가중치 + 에이전트 코드 | 낮음 |

## 3. 할루시네이션의 구조적 이해

{/*
  - LLM이 자기 머릿속(Procedural Memory)에만 갇혀서 추론하는 것이 문제
    - 외부 세계를 확인하지 않고, 내부 지식만으로 사고를 전개
    - Semantic Memory가 비어있을 때 → 그럴듯한 거짓말
  - 이것이 환각(hallucination)의 구조적 원인

  - 에이전트 행동의 가독성(legibility)과 human alignment
    - 에이전트가 왜 그런 행동을 했는지 읽을 수 있어야 함
    - 어디서 잘못됐는지 진단할 수 있어야 함
    - 최소한의 개입으로 궤적을 바로잡을 수 있어야 함

  - 이것이 1편의 "세션 분리 리뷰"와 2편의 "CONTEXT.md"를 정당화하는 이론적 근거
*/}
